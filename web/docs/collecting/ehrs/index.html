EHR reports

This page sets out what a site's report writer has to produce from the EHR, whichever EHR the site uses. Recipes for specific EHR products will be added as they're written. Until then, this page is the specification any EHR's reports should meet.

Sites with a registry need only the first four reports; EHR-only sites need all eight. A site with a FHIR export can skip the first four reports: the calculator reads FHIR for patients, coverage, visits and PHQ results. The columns match the data contract. Start from the CSV templates: one file per table, with the column headings the calculator expects. The calculator page checks each file and lists any rows it can't use. Asking for the data has ready-to-send requests for each report.

Reports every site needs

ReportOne row perColumnsRules
PatientsPatient in any other reportPatient id, date of birthOne patient id
CoverageCoverage period overlapping the monthPatient id, payer category, plan name, start date, end dateEvery period, not just the current one. Medicaid
Practice visitsVisit in the monthPatient id, visit date, provider category, billing codes, modalityEvery visit, all payers; the calculator applies the qualifying-visit rule. Screening
PHQ resultsScored PHQ-2, PHQ-9 or PHQ-A in the last 13 monthsPatient id, date administered, instrument, total scoreEvery questionnaire, flowsheet row and observation that holds one, from every department. Screening

Reports for sites with no registry

ReportOne row perColumnsRules
CoCM episodesEpisode overlapping the monthPatient id, enrollment date, enrollment source, primary condition, primary scale, discharge date, discharge reasonFrom a program-enrollment record if the EHR has one; otherwise inferred from billing and disclosed. Enrollment and discharge
ContactsBHCM or CoCM-team encounter since each episode beganPatient id, date, staff role, kind (treatment, outreach attempt, scheduling, no-show, message), modalityEncounter type alone rarely shows treatment; require a signed note. Contacts and reviews
Monitoring scalesScored NYS scale since each episode beganPatient id, date, instrument and form, total scoreAll seven NYS scales and each form separately. Scales and outcomes
Case reviewsPatient reviewed by the consultant in the last 60 daysPatient id, review date, recommendation documentedOne row per patient, never per meeting. Contacts and reviews

What a recipe for a specific EHR adds

For each report above:

  • which tables, reports or extracts supply it;
  • which encounter types, departments, questionnaire and flowsheet IDs, and provider types to include;
  • the traps particular to that EHR.

There are no recipes yet. Which EHRs to write them for first depends on which ones NYS's CoCM sites use most (tooling plan).
