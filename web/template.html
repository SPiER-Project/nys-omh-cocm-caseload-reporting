2. Patient ids (optional)

To keep MRNs out of the results, load your site's pseudonym key before adding files. Each patient id is then replaced with a pseudonym made from it with the key, so the same MRN gets the same pseudonym from every file and every month. Patient ids should be MRNs, so the registry and the EHR agree.

No key: patient ids are used as they are.

3. Your data

Add the reporting workbook, or one CSV file per table in the data contract's shape, named after the table (for example patient.csv). Sites with a FHIR export from their EHR can add it too (.json or .ndjson): it fills in patients, coverage, visits and PHQ results. Everything you add is combined. A table you don't add is treated as empty.

No workbook yet? Download the blank workbook, or an example filled with invented patients. It opens in Excel, Google Sheets, Numbers or LibreOffice. Producing CSVs from your systems instead? Download the CSV templates (one file per table, with its headings) or the example as CSVs.
